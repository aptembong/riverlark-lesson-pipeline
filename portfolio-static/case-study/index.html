The situation

Riverlark's Texas team counted 178 TEKS reading standards with no practice lesson behind them, and fall 2027 classrooms were the deadline. The request came in as "fill the STAAR gap by fall."

Discovery changed the question. With three editors reading every passage, review time limited the schedule more than writing did, and most passages came back for routine reasons: the wrong length, sentences too long, or a skill mentioned once instead of taught. Representation needed a person's judgment every time.

What the pipeline does

  • Turns each standard into a lesson brief with grade-level targets.
  • Fills a versioned prompt, and Claude drafts the passage with its skill examples quoted exactly from the text.
  • Checks every draft and sorts it into green, yellow or red before a person sees it.
  • Sends editors every yellow and a 10% sample of green. Red is redrafted.
  • Builds a gradual-release lesson (Hook, I do, We do, You do, Recap) and a text-first video.
  • Changes prompts only through a tested, reversible process.

Quality and governance

Checks sort. People decide.

Each passage gets three layers of quality control. Automation handles what it can count, editors handle judgment, and an expert reviews a sample of each batch. Prompts change only through a written, tested process.

LAYER 1 · EVERY PASSAGE

Automated checks

Schema, length, sentence length, skill evidence, readability estimate, representation word lists. Assigns a lane in seconds.

LAYER 2 · EVERY YELLOW, 10% OF GREEN

Editor review

Skill alignment, clarity, grade fit, representation. Approve, approve with notes, regenerate or reject.

LAYER 3 · 5% OF EACH BATCH

Expert review

A representation consultant reads a deep sample. The Managing Editor approves each batch before video.

The three lanes

These are the rules in pipeline/validate.py. They're fixed before a batch runs and never tuned to the batch they score.

Green

Every check passed.

Goes to the editor queue as a 10% random spot-check, about 30 seconds each.

Yellow

Any fit issue, or one or two yellow-list words.

An editor reads all of it with the full rubric, about 3 minutes each.

Red

Any red-list word, three or more yellow-list words, or a broken schema or misquoted skill example.

Never reaches review. It's redrafted and checked again.

Representation framework

Five things editors look for. The rules are also in the prompt itself.

  • Agency. The main character solves their own problem. There's no outside rescuer.
  • Everyday culture. Culture, family and place appear as ordinary life, never as something exotic or a problem.
  • No stereotypes. No "naturally gifted," no model-minority or deficit shortcuts.
  • Range across the library. Over 178 lessons, every student should see themselves somewhere.
  • Asset-based language. Person-first or neutral words for disability, and no "at-risk" or "broken home."

The word lists can only flag words. Whether a story treats its characters well takes a person to judge, so representation always has a human layer.

I check the checks too

The first version of the validator flagged "authentic" near "culture" as a stereotype. That penalized exactly the language the framework asks writers to use, so v2 removed the pattern and recorded why in the code.

Readability, honestly labeled

Lexile is a licensed measure. The validator uses a free Flesch-Kincaid grade estimate only to route passages. Riverlark's licensed Lexile analyzer stays the final gate before an editor approves.

Prompt change process

Used for real: PR-2026-11-01

The approval bar is written down before the test runs, so a result can't move the goalposts.

1. ProposeWhat the last run showed, likely causes, the exact change, and what stays the same.
2. TestSame sample briefs, same validator, fresh first drafts saved before scoring. No edits after.
3. ApproveManaging Editor checks the result against the bar set in step 1. Approve, approve with conditions, or reject.
4. Roll backThe old prompt stays in the repo. Rolling back means pointing the renderer at it. No other file changes.

What changed in v2.1

  • A target word count and paragraph plan, in place of a bare range.
  • A per-sentence cap, with an instruction to split long sentences.
  • Vocabulary guidance by grade band, in place of a bare Lexile number.
  • A self-check on counts before returning.
  • No change to the schema, rules, representation guidance or validator.

Readability: v2.0 ran hard, v2.1 runs slightly easy

Flesch-Kincaid grade estimate for each passage. The green band is the expected range for that grade. A red ring means outside the range.

v2.0v2.1expected range

Every length and sentence-length miss is fixed. But readability dropped in every band, and seven passages now sit within half a grade of the floor or below it. Passing isn't the same as centered, so the next change aims for the middle of the range.

What this shows

  • On these 20 briefs, v2.1 fixed every length and sentence-length miss without breaking anything that passed.
  • Skill evidence is checkable: all 20 passages in both runs quote their examples exactly.
  • The change process works: the bar was set first, then met, then approved with conditions.

What it doesn't show yet

  • That v2.1 generalizes. The fix was designed from these same briefs, so fresh holdout briefs come next.
  • That the estimate matches Lexile. Only the licensed analyzer can show that.
  • A blind test. Claude drafted both runs knowing what the validator checks.
  • Editor and teacher judgment. That comes in the pilot.

Adding a new state

Planning estimate · 2-3 weeks
  • Swap the standards list and codes (Stage 1).
  • Map the state test's question formats to the You do check.
  • Confirm readability targets per grade.
  • Have the representation consultant review guidance for the state's students.
  • Run the 20-brief sample test before production.

Planning estimate · 3-4 weeks
