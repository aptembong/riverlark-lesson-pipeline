Prompt change process

No prompt reaches production without a written proposal, a test on the sample set, a recorded decision and a way back. The same steps apply to validator rules. Used once so far, for PR-2026-11-01.

Process in useWorked example is the real v2.0 → v2.1 change

When to open a change

Open a change request
  • Fewer than 90% of reviewed passages in a batch are approved. Generation pauses until a change is approved.
  • The same send-back reason shows up three or more times in a week.
  • A band's first-pass green rate falls below its bar for a batch.
  • The monthly readability audit shows drift in a band.
  • A new grade band, state or subject is added.
  • The model version changes. A new model is a prompt change too.
  • A wrong-lane pattern points to a validator rule. Rule changes follow the same steps.
Not a change request
  • One weak passage. Regenerate it with a note.
  • A one-off fix an editor can make with Approve with notes.
  • Anything that would change a rule to pass a batch already scored.

Anyone can ask for a change: writers, editors, the consultant or the Managing Editor. AI Workflow writes it up and runs the test.

Rules that keep the test honest

The bar comes first. It's written before the run, so a result can't move the goalposts.

One change at a time. A prompt and a validator rule never change in the same request, or you can't tell which one worked.

Then fresh briefs. A change designed from the sample set is confirmed on holdout briefs before production.

Worked example: PR-2026-11-01
Real change, run Nov 2026

    

      
Proposal · v2.0 → v2.1

        
What the last run showed. v2.0 on the 20 sample briefs: 8 green, 12 yellow, 0 red. Every yellow came from fit checks, not content or safety: 5 passages under the word range, 6 with sentences too long, 7 reading too hard and 1 too easy.

        
Likely cause. The prompt gave a range and nothing else, so drafts aimed at the bottom of it. It gave an average sentence length with no cap. A Lexile number alone doesn't tell the writer what to change.

        
The change.
  1. A target word count and a paragraph plan, in place of a bare range.
  2. A per-sentence cap (top of the range plus 8 words), with an instruction to split long sentences.
  3. Vocabulary guidance by grade band, in place of a bare Lexile number.
  4. A self-check on counts before returning.

        
What stays the same. Output schema, content rules, representation guidance and the validator. No other file changes.

Decision, Nov 15, 2026: approved with conditions. Approved for the next pilot batch. First, run v2.1 on fresh briefs it wasn't designed from. Second, open the next change to center readability, because v2.1 overcorrected and now reads slightly easy.
